```txt
lawlint [options] <file.txt|file.md|file.docx|->
lawlint init [options]
lawlint learn <path> [options]
lawlint rules [--json]
lawlint rules test <path> [options]
lawlint self-update [options]
```

The file argument defaults to `-` (stdin), so a bare `lawlint` reads a pipe.

### Model specs

`--judge=MODEL`, `init --ai`, and `learn --model` share one grammar:

| Spec | Provider |
| ---- | -------- |
| `anthropic:<model>` | Anthropic |
| `openai:<base-url>#<model>` | Any OpenAI-compatible endpoint |
| `foundry:<deployment>` | Azure AI Foundry |

`init --ai` additionally accepts the shorthands `qwen` and `gemma`.

## `lawlint init`

Sets up the project: AI-model, judge, Markdown, and custom-rule choices, written
to `.lawlint/config.json`. API keys go to a user-level credential file, never
into the project.

<TypeTable type={{
  "--yes": { type: "flag", description: "Accept the default answer for every prompt (non-interactive)." },
  "--force": { type: "flag", description: "Overwrite an existing .lawlint/config.json." },
  "--ai": { type: "MODEL", description: "Model preference, skipping the catalog prompt: qwen, gemma, or a full spec." },
}} />

See [Setting up AI features](/docs/guides/ai-setup).

## `lawlint learn <path>`

Mines a style rule package from source writing, your own or exemplars you want
drafts to match. It profiles the full corpus, drafts AI versions of sampled
passages as a contrast set, mines hard and soft rules from the difference, and
keeps only rules that never flag the corpus and (for mined rules) flag at least
one AI draft. The package also carries `profile.json` and a `STYLE.md` drafting
brief.

<TypeTable type={{
  "PATH": { type: "path", required: true, description: "A file or directory of source writing (.docx, .md, .txt)." },
  "--out": { type: "DIR", default: ".lawlint/rules/personal", description: "Where to write the generated rule package." },
  "--model": { type: "MODEL", description: "Mining model, overriding the lawlint init AI preferences." },
  "--workers": { type: "N", default: "4", description: "Concurrent mining workers (1-4), overriding learn.concurrency." },
  "--contrast": { type: "N", default: "6", description: "AI drafts of sampled passages to mine against; 0 disables the contrast set and the discrimination check." },
  "--no-soft": { type: "flag", description: "Skip soft (AI-judge) rules and the judge calls that verify them." },
}} />

See [Learning a style](/docs/guides/learn).

## `lawlint rules`

```sh
lawlint rules --json
```

Prints metadata for every loaded rule — id, tier, scope, severity, description,
intent, rationale, and documentation URL — as JSON. Combine with `--rule-dir` to
include a package.

### `lawlint rules test <path>`

Runs each Markdown rule's own flag and pass examples and reports the result per
example.

## Exit codes

| Code | Meaning |
| ---- | ------- |
| `0` | No error-severity findings, and warnings within `--max-warnings`. |
| `1` | An error-severity finding, or warnings over `--max-warnings`. |
| `2` | An I/O or configuration error — the document was never linted. |
